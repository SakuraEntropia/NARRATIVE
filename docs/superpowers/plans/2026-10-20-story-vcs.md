# Story Version Control Implementation Plan

**Goal:** Add Git-inspired story workflows while preserving legacy SQLite data.
**Architecture:** Immutable content blobs and commit DAG; mutable refs/HEAD and persistent whole-story working copy; structured three-way merge with explicit conflicts.
**Tech stack:** Existing Python 3.12+, SQLite, Pydantic, pytest.
**Spec:** docs/superpowers/specs/2026-10-20-story-vcs.md.

## Global constraints

Legacy snapshots/history remain immutable and untouched. No silent canon promotion or locked overwrite. Dirty data must survive refused checkout. Reject stale writers atomically. No external APIs required for tests.

- [x] Implement/test pure structured merging in core/merge.py: disjoint fields, equal edits, add/add, modify/delete, null/missing, atomic lists, version counters and conflict choices.
- [x] Implement/test commit/ref/HEAD persistence and idempotent legacy migration in core/versioning.py plus small focused support modules when needed.
- [x] Add working state, checkout, branches/tags, revision resolution/log/show/diff and optimistic transaction guards; preserve old public methods.
- [x] Implement merge/revert state machine with validation, conflict persistence/resolution/abort and hard canon guards.
- [x] Integrate CLI operations and test end-to-end workflows, including migration and rejected writes.
- [x] Update README/API/architecture/limitations and version-control guide; run full suite/lint and save results.
- [x] Commit, push and verify GitHub CI for all supported Python versions.

Additional verified surface: reflog inspection, explicit CLI commit author, clean/blank commit policy, immutable-ID precedence, stale content-alias and refreshed-read protection.

# Story version control design

## Goal and scope

Provide Git-inspired local story version control atop existing SQLite data. Keep immutable story blobs separate from commit identities; commits form a DAG with ordered parents, message, author and timestamp. Named branches/tags, symbolic/detached HEAD and a persistent whole-story working copy support alternate story histories. This is story versioning; it does not invoke Git for each story, track arbitrary files, or introduce network remotes/staging subsets.

## Persistence and compatibility

Existing snapshots/history tables and immutability triggers remain intact. Add vcs_commits (id, snapshot, parents JSON, message, author, created, metadata JSON), vcs_refs (qualified name, target), vcs_state (singleton symbolic/detached HEAD, working JSON, base, revision) and immutable vcs_reflog. Commit IDs hash blob+parents+metadata+nonce; repeated content has one blob but distinct commits. Legacy history rows become distinct deterministic commits in sequence, with parent snapshot mapped to latest earlier occurrence; ambiguous legacy ancestry is recorded. No legacy row is rewritten. Atomic migration is versioned and idempotent.

Default load reads working copy; explicit load reads immutable revisions. Project.version is an identifier excluded from blob hashing. Legacy content hashes remain load/diff aliases; ancestry operations reject ambiguous content aliases. Existing commit(graph,parent,message,authorized_locked) auto-commits whole graphs, but explicit parent must match current HEAD. Separate branch/checkout operations represent divergence. history() remains all commits oldest first with legacy-compatible version/parent fields.

## Public API contract

`SnapshotStore` retains commit/load/history/diff/close and adds:

- `status() -> dict`: branch (short name or null), head, detached, dirty, revision, changes.
- `save_working(graph, authorized_locked=None) -> dict`: validate/save uncommitted graph.
- `commit_working(message, author='human', authorized_locked=None) -> str`.
- `branches() -> list[dict]`, `create_branch(name,start=None) -> dict` (does not switch).
- `tags() -> list[dict]`, `create_tag(name,target=None) -> dict` (immutable names).
- `checkout(revision, discard_changes=False) -> dict`: branch attaches; tags/commit detach.
- `log(revision='HEAD', all_branches=False, limit=100) -> list[dict]`: parents/evidence visible.
- `show(revision='HEAD') -> dict`: commit metadata plus graph document.
- `resolve(revision='HEAD') -> str`: commit ID, branch/tag, unique prefix >=7, HEAD~N / HEAD^N.
- `merge(revision,message=None,authorized_locked=None) -> dict`: ancestor/up-to-date, fast-forward or two-parent merge; divergent conflicts persist and no commit occurs.
- `revert(revision,message=None,authorized_locked=None) -> dict`: inverse commit delta applied to current HEAD; merge commits require explicit mainline selection (unsupported here, return error).
- `resolve_conflicts(resolutions: dict[str,str]) -> dict`: choose ours/theirs/base per reported JSON pointer path, then stage merged work; explicit commit finishes merge/revert.
- `abort_merge() -> dict`: restore exact pre-operation working state when an operation is pending.

No destructive branch reset/delete in this release. Checkout --discard-changes is explicit. Commit and active working mutations compare loaded HEAD/revision under BEGIN IMMEDIATE; stale writes fail without orphan commits. Locks and canon promotion are checked against target HEAD, plus both parents when merging. Append-only records prevent application-level history rewrites, not owner tampering with SQLite.

## Structured merge contract

`core/merge.py` exports `merge_documents(base: dict, ours: dict, theirs: dict, resolutions: dict[str,str] | None = None) -> dict` containing `document`, `conflicts` (path, base/ours/theirs values and existence flags, reason). Nodes/edges are maps by stable ID for merge, converted back to sorted lists. Dict fields merge recursively; ordered lists are atomic. Missing and JSON null differ. Derived record version counters do not create artificial conflicts and are recomputed monotonically. Project.version is ignored. Source snapshots never mutate. Conflict choices replace only their scoped path, not unrelated graph data.

Merge bases use the full parent DAG. Reject unrelated histories and multiple maximal common ancestors unless an explicit recursive-base implementation exists. Validate merged graph, canon protections and forward state transitions before committing; structural/simulation failures leave HEAD unchanged and return actionable findings. Fast-forward cannot discard pending changes or bypass locks. Revert applies inverse delta via merge_documents(reverted commit, current HEAD, first parent), preserving unrelated later edits.

## CLI

Existing auto-commit init/ingest/refine/approved pivot remain compatible. Add status, save FILE, commit -m MESSAGE, branch [NAME] [--start REV], tag [NAME] [--at REV], checkout REV [--discard-changes], switch BRANCH, log [REV] [--all] [--limit N], show [REV], merge REV [-m MESSAGE] [--authorize-locked ID], merge --resolve PATH=ours|theirs|base, merge --abort, revert REV [-m MESSAGE] [--authorize-locked ID]. Diff supports zero args (HEAD→working), one arg (revision→working), two refs. Every command returns JSON and failures return nonzero status.

## Verification

Tests cover real v1 migrations including duplicate blobs, persistence and immutable DAG, branch isolation/reload, detached HEAD, old aliases/ref parsing, dirty checkout protection, concurrent stale writes, three-way conflict cases, conflict resolution/abort, multi-parent merges, reverted patch preserving later changes, locked canon/promotion, simulation regression rejection and complete CLI workflows. Full prior suite remains required. Document exact limits and push tested changes to the existing repository.

Implementation additions: inspectable `reflog(limit)` / `reflog --limit N` records HEAD/ref and pending-operation transitions; `commit --author NAME` supplies author metadata. Exact full commit IDs take precedence over refs. Clean ordinary `commit_working` and blank messages/authors are rejected; compatibility whole-graph `commit` still permits repeated content. Root and merge-commit reverts are unsupported.
